# 委托手续制作

复用随 Skill 打包的离线 HTML 生成器和 Word 模板。模型整理材料及复核，本地程序填充模板。现有范围：一审、二审、再审、执行、仲裁申请人及被申请人；同一程序立场的多名客户分别生成。内置的是当前汉坤模板，不能把它当成适用于任意律所的通用模板。

## 选择信息进入模型的范围

- 用户仅要求打开工具，或明确要求真实信息留在本地时，运行下面的本地入口。由用户在独立浏览器填写和下载；模型只说明操作，不读取真实表单、下载目录、文件内容、截图或映射表。用户未选择模型辅助且未提供材料时，优先采用此入口。
- 用户已提供材料并要求提取信息、代填或制作文件时，采用模型辅助流程。只读用户提供或明确指定的当前材料，说明这些内容会进入模型处理。本地生成不能消除已经发生的模型读取。
- 用户要求先脱敏时，不先读取原文再称为“上传前脱敏”。让用户在独立本地流程准备必要片段，或接入已核验的本地脱敏工具；本 Skill 不包含自动识别人名、公司名的脱敏引擎。

隐私边界、工具输出及共享范围见 [references/privacy.md](references/privacy.md)，涉及保密要求时读取。Skill 的行为约束和页面禁止联网不能代替宿主的文件访问隔离。

## 本地填写入口

将路径替换为当前 Skill 的真实目录：

    python3 "<skill-dir>/scripts/open_local.py"

该入口打开 `assets/generator.html`，无需 Node、联网服务或模型填表。脚本只返回打开状态。若无法自动打开，向用户提供该 HTML 的本地文件链接。真实表单填写后不再用浏览器工具接管这个页面。

用户在页面选择具体的本所客户、程序及文件，填写后本地生成 Word 并下载。页面沿用内置特别授权条款，已禁用无法安全转换的一般授权选项。由用户查看真实成品；模型不能把未读取的内容复核或版式核验写成已完成。

## 模型辅助生成

首次运行前读取 [references/input-schema.md](references/input-schema.md)。按该格式准备独立的 UTF-8 JSON 参数文件，将关键字段依据记入 `analysis.sources`；材料有歧义时记入 `unresolved`，保留 `draft`，不强行生成确定文书。

整理信息时保留这些边界：

- 全部当事人和本所客户分别记录。客户必须由材料或用户指令明确；同方其他当事人不自动成为客户，也不因未选中而变成对方。
- 主体类型逐一判断；名称、程序地位、地址、法定代表人或负责人、承办律师及落款日期来自当前材料。自然人不套用法人身份证明模板。
- 二审、再审、执行及仲裁角色不能按一审原被告机械映射。客户处于不同程序立场时当前工具停止生成。
- 内置授权委托书正文包含特别授权及转委托事项。只有用户或材料明确采用这些模板权限时才写 `analysis.authorizationBasis`。现有模板的一般授权只改标签，程序已阻止该输出；需要一般授权或逐项授权时，使用另行审定的模板工作流，不自动删改条款后宣称沿用当前模板。
- 费用、税费、费用承担、协议争议解决机构和冲突豁免来自实际委托口径。只生成授权书或所函时，不要求填写律师费。冲突豁免不能因识别到主体关联就自动勾选。
- 只生成主体身份证明时仍需当前工具要求的案件公共字段。自然人单独选择身份证明会被阻止；与其他文件一起选时会跳过该项并返回数量。

本地运行需要 Node 18 及以上、Playwright/Chromium 和 Python 3.10 及以上。优先使用客户端已提供的依赖及浏览器；缺项时按 [references/runtime.md](references/runtime.md) 准备，依赖安装只接触程序包。

    node "<skill-dir>/scripts/generate.mjs" --input "<task-dir>/plan.json" --output-dir "<task-dir>/outputs/run-01"

输出目录必须尚不存在。程序校验输入，调用同一个离线生成器，写入中性文件名的 DOCX、`source-plan.json`、`manifest.json`，再调用独立结构核验。标准输出只有状态、数量及问题代码，不含姓名、证件号、地址或文件正文。失败退出码为 2，失败目录清理；修正参数后使用新输出目录重跑，不以旧成品替代本次结果。

单独核验已经生成的包：

    python3 "<skill-dir>/scripts/verify.py" --bundle "<task-dir>/outputs/run-01"

## 复核并交付

程序核验覆盖 DOCX 完整性、客户及相对方、程序、自然人跳过规则、代表人、律师和落款日期，以及模板内部标记；它不能判断材料提取是否正确、授权是否充分或最终排版是否合适。

模型辅助流程下，对照原始材料核对参数与生成文件，重点查客户选择、程序地位、授权原文、费用及签章栏。可用渲染器时渲染最终 DOCX 并查看页面；仅通过结构核验时如实说明视觉检查的范围。把实际完成的模型复核写入任务输出目录的 `model-review.md`，不要预填“已核验”。

本地填写流程下，由用户查看文书或运行本地核验；只有用户另行授权把指定内容交给模型后，才读取这些内容。用户主动提供的脱敏页只能支持对这些页的检查，不能据此声称全文正确。

交付所需 Word 文件和必要的口径、缺项及核验说明。内置分所地址、账户及条款来自打包模板，正式使用应与当前委托口径核对。对外发布只包含有权共享的代码、模板和虚构样例；实际案件参数、下载文件、模型复核记录及测试产生的案件包不进入公开仓库。
